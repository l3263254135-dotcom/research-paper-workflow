# 首投验收与状态核查

按目标刊的现行官方说明验证。记链接、查阅日期、文章类型、政策口径与门户现场校验差异；不要把单个历史截屏里的篇幅、字段数量、费用或勾选当今天的通用规则。复用 [submission-revision](../skills/submission-revision/SKILL.md) 做投稿材料审核。

## 五个需要分别确认的问题

| 问题 | 通过凭证 | 不能代替它的东西 |
|---|---|---|
| 证据够不够？ | 主张追到结果，限定和反例可见；独立复核了决定方向的证据 | 多改几版、更多引用或模拟接收率 |
| 最终文件对不对？ | 从同一冻结版本产出的主稿、SI、数据/代码包、投稿信与元数据一致；从 PDF 回读文字并实看图；干净解压最终 ZIP，比清单、入口权限、依赖和可再生结果，必要时跨平台运行 | 源稿能编译、工作目录能运行、机器预检零失败 |
| 评审真能拿到数据吗？ | 按政策记录评审和出版两个时期各自可访问的材料、入口和版本。整理覆盖范围：从原始输出、从派生序列复算、或只从中间结果复图。验证实际评审入口或记录未验证之处；用 DOI 引用正确记录，精确声明限制和未交付部分 | DOI 能解析但文件锁定；提交了 ZIP 但未经配置为审稿附件；作者自己登录能下载 |
| 作者真的确认了吗？ | 全作者知情并核对最终稿，通讯作者确认署名、机构、基金与持有人、相关稿件、利益冲突、AI 披露、权限及许可；推荐审稿人由作者逐一检查独立性 | 技术通过、表单已有 initials、或旧版批准 |
| 外发是否授权？ | 分别确认提交期刊、数据归档公开、预印本转发及任何涉及第三方的操作；通过作者提供的审稿或收据证据确认状态 | 自动填表、预留标识、创建稿件编号、已上传文件 |

## 文件与门户是两层证据

- 从实际交付 ZIP 解压验证，不只检查打包目录。将原数据访问和派生材料复现分开，说明脚本和材料覆盖边界；无法再获得原始文件时不留“稍后会随包提供”的承诺。临时评审访问按期刊允许的通道，不把凭证或访问令牌放入公开主稿、模板或日志。出版前再核约定的访问方式。
- 记录本地需上传文件的版本、名称、角色、哈希和页数。由作者打开门户合并稿、转换版与独立 SI，在最终显示比例检查图、图注、引用和补充材料；区分同一文件的 Source 与 Converted PDF。若未下载门户原件比对，就只声明已比对本地文件、门户类别或可见内容，不宣称字节一致。
- `NOT_READY_FOR_SUBMISSION`：任一必要的科学、访问或声明要求未满足。`READY_FOR_AUTHOR_SUBMISSION`：检查完成、交作者决定和操作，不等于已外发。`SUBMITTED`：匹配稿号的正式回执或明确提交后阶段；记录证据时间与门户原文。`ACCEPTED`、`PUBLISHED` 各需相应通知或发表记录。初步质量检查不等于外审或接受。
- 冻结实际首投文件、表单与附件映射、回执、未决随访；留到返修和可追溯归档。此技能不代为登录门户、批准文件、提交、公开仓库或删除项目资料。
